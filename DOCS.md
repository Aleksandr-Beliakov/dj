# DiJuly — документация по сайту

Внутренняя документация проекта. Не часть самого сайта (не подключается нигде
в `index.html`), лежит в репозитории, чтобы не потерялась и была под рукой
при следующих правках.

## Что это за сайт

Одностраничный статический сайт на чистом HTML/CSS/JS, без сборки, без
фреймворков, без зависимостей (кроме шрифта Google Fonts). Хостится на
GitHub Pages, домен `dijuly.com` подключён через файл `CNAME`.

Исходно сайт был собран на Elementor (WordPress) — эта версия является его
переносом на чистый код с сохранением визуала (см. `git log` — самые первые
коммиты про «сборку»).

## Дизайн-система (токены)

Формального style-guide файла нет, вся «система» — в inline `<style>`
внутри `index.html`. Если добавляете что-то новое — держите в этих рамках:

- **Шрифт:** Montserrat (300 / 400 / 500 / 600), подключён с Google Fonts.
  Фолбэк — `sans-serif`.
- **Палитра:** строго чёрно-белая. Фон `#000`, текст `#fff`. Никаких ярких
  акцентных цветов в UI (цветные — только оригинальные логотипы соцсетей).
- **Читаемость текста на фото:** через `text-shadow: 0 2px 10px rgba(0,0,0,.65)`,
  а не через цветные подложки/прямоугольники.
- **Вёрстка секций:** широкоформатные фото на всю ширину (`width:100%;
  height:auto`), текст/UI поверх — через `position: absolute` внутри
  `position: relative` контейнера секции. Один брейкпоинт:
  `@media (max-width: 767px)`.
- **Интерактив (hover/focus):** плавные переходы `transition: ... 0.2s ease`,
  обычно через `opacity`. Видимый `:focus-visible` outline — обязателен для
  любого нового интерактивного элемента (кнопки, ссылки).
- **Скругления:** где нужны — `border-radius: 2px` (унаследовано от
  оригинального Elementor-дизайна).

5. **Галерея** (`.gallery`) — карусель-«веер» фотографий диджея, сразу под

## Переключатель языка (i18n)

- Файл: `assets/js/i18n.js` — там и словари (en/ru/es), и вся логика.
  Один файл, а не три (`en.js`/`ru.js`/`es.js`), сознательно: на сайте и так
  нет сборки, лишние HTTP-запросы ради десятка строк текста не оправданы.
- **Язык по умолчанию — английский**, всегда, независимо от языка браузера.
  Язык браузера (`navigator.language`) **намеренно не используется**.
- Выбор языка хранится в `localStorage` под ключом `dj_lang` и применяется
  при следующих визитах. Если `localStorage` недоступен (приватный режим и
  т.п.) — просто всегда показывается английский, без ошибок.
- В переключателе всегда видно **ровно 2 кнопки** — те языки, что не
  являются текущим (все 3 кнопки есть в DOM всегда, активная скрывается
  через атрибут `hidden`).
- Чтобы не было «мигания» английского текста перед сменой на сохранённый
  RU/ES: в HTML изначально прописан английский текст (как язык по
  умолчанию), а `<script src="assets/js/i18n.js">` стоит прямо перед
  `</body>` **без** `defer`/`async` — выполняется синхронно во время
  парсинга, до первой отрисовки страницы браузером.
- **Как добавить новую переводимую строку:**
  1. В `index.html` добавить элементу атрибут `data-i18n="какой-то_ключ"`
     (подменяет видимый текст) или `data-i18n-aria="какой-то_ключ"`
     (подменяет `aria-label` — для кнопок-иконок без текста, например
     стрелки галереи).
  2. В `assets/js/i18n.js` добавить `"какой-то_ключ": "..."` в каждый из
     трёх словарей (`en`, `ru`, `es`).
  3. Если какому-то другому скрипту (как `gallery.js`) тоже нужно
     локализовать то, что он сам рисует в JS — подписаться на
     `document.addEventListener("dj:langchange", ...)`, которое
     `i18n.js` кидает при каждой смене языка.
- **Что сознательно НЕ переводится** (бренд-элементы, по решению заказчика):
  `DiJuly`, `Dressed in Sound`, жанры (`Pop Dance Disco House`), названия
  тарифов `Basic` / `Standard` / `Premium`, цены (`$100` и т.п.).
- Что переводится сейчас: условия тарифов («до N часов») и
  `<meta name="description">`.
- `aria-label` у кнопок переключателя локализован на **текущий активный**
  язык (например, если сайт на русском — у кнопки EN будет
  `aria-label="Переключить на английский"`).

## Hero: имя, слоган, жанры

Переделано с нуля в ноябре 2025 (до этого был вариант с тремя простыми
абсолютно спозиционированными строками `DiJuly` / `Dressed in Sound` /
`Pop Dance Disco House`, без плашки и без «плавающих» жанров — если
понадобится найти старую версию, она в истории git до коммита
`551a360`).

- Файлы: вся разметка/стили — в `index.html`, блок `/* ---- Hero: плашка
  с именем и слоганом, строка жанров, затемнение снизу ---- */`. Слоган
  раскладывается на буквы отдельным скриптом `assets/js/hero-tagline.js`.
- **Разметка:**
  ```html
  <section class="hero">
    <img ...>
    <div class="hero__scrim"></div>
    <div class="hero__plate">
      <h1 class="hero__name">DiJuly</h1>
      <p class="hero__tagline"></p>  <!-- буквы вставляет hero-tagline.js -->
    </div>
    <ul class="hero__genres">
      <li>Pop</li><li>Dance</li><li>Disco</li><li>House</li>
    </ul>
    <div class="lang-switch">...</div>
  </section>
  ```
  `.hero__scrim` стоит в DOM **сразу после `<img>` и перед текстом** —
  специально, чтобы затемнение лежало визуально под текстом, но над фото
  (стэкинг по порядку в DOM, без z-index).
- **Плашка имени (`.hero__plate`)** — **без фона** (чёрный фон был в
  первой версии редизайна, заказчик попросил убрать — текст лежит прямо на
  фото, читаемость через `text-shadow: 0 2px 10px rgba(0,0,0,.65)`, как и
  everywhere на сайте). `.hero__name` — обычный `<h1>DiJuly</h1>`,
  капитализация через `text-transform: uppercase` в CSS (в разметке текст
  остаётся `DiJuly`, семантика не менялась).
- **Слоган (`.hero__tagline`)** — пустой `<p>` в разметке, буквы вставляет
  `assets/js/hero-tagline.js`: каждая буква — отдельный `<span
  aria-hidden="true">`, пробелы между словами — `<span
  class="hero__tagline-space">` фиксированной ширины (fluid, см. ниже).
  Сам `<p>` — `display:flex; justify-content:space-between` — при
  `align-items:stretch` на родителе `.hero__plate` (`display:inline-flex;
  flex-direction:column`) ширина `.hero__tagline` **автоматически
  становится равна ширине `.hero__name`** (стандартное поведение flex-
  stretch), а `space-between` равномерно распределяет буквы на всю эту
  ширину — поэтому слоган всегда ровно под именем, на любом языке/ширине
  экрана, без ручной подгонки пикселей.
  - Слоган — **бренд-текст, не переводится** ни на одном языке (как и
    жанры), поэтому строка `"Dressed in Sound"` зашита в самом
    `hero-tagline.js`, а не в словарях `i18n.js`. Скрипт перестраивается
    на `dj:langchange` на случай, если это когда-нибудь изменится.
  - `padding-left/right` у `.hero__tagline` выставляет **JS**
    (`align()` в `hero-tagline.js`, пересчёт на resize и после загрузки
    шрифтов) — так, чтобы края **видимых букв** слогана совпадали с
    краями видимых букв имени. Почему это нужно — см. «Решённые баги»
    ниже («Слоган вылезал за край имени»).
- **Жанры (`.hero__genres`)** — `<ul>` с `Pop/Dance/Disco/House`,
  разделители — тонкие вертикальные чёрточки через `li + li::before`
  (не текстовые `|`, не точки).
  - **На ПК — «плавающая» строка**: `position: sticky; bottom: ...`
    относительно `.hero` (прямого родителя `<ul>` — у sticky это и есть
    та «containing block», в границах которой элемент перестаёт
    прилипать). При загрузке страницы стоит у нижнего края экрана, при
    прокрутке остаётся там же, пока не долетит до своего обычного места
    (нижний край hero-фото) — дальше вниз не уезжает, просто остаётся на
    месте и уходит вместе со страницей дальше. Проверено скроллом через
    реальный Chrome (CDP, `window.scrollTo` + `getBoundingClientRect()` на
    разных позициях скролла) — элемент и правда «прилипает», а потом
    корректно «отлипает» точно у границы `.hero`.
  - **На мобильных (`@media max-width: 767px`) sticky отключена** —
    `position: absolute` (как раньше), жанры всегда у низа hero-фото,
    не плавают. Так просил заказчик.
  - Горизонтальный отступ жанров — через **`padding-left`, а не `left`**:
    у `position: sticky`-элемента свойство `left` ведёт себя как у
    `position: relative` (сдвиг от «статичной» позиции в потоке) и
    применяется только когда на странице **возможен горизонтальный
    скролл** — здесь его никогда нет, так что `left` просто
    игнорировался бы браузером (проверено практически — буквы съезжали к
    самому левому краю экрана). `padding-left` работает одинаково что в
    sticky-, что в absolute-режиме (на мобильных).
  - **Важный сопутствующий фикс**, без которого sticky вообще не работал:
    `overflow-x: hidden` раньше висел на правиле `html, body { ... }`
    одновременно. По спецификации CSS, если задать `overflow-x` без
    `overflow-y`, браузер молча выставляет `overflow-y: auto` для того же
    элемента — из-за этого `<body>` становился «scroll-контейнером», и
    `position: sticky` внутри него переставал работать вообще (элемент
    просто скроллился вместе со страницей, как обычный `absolute`/`static`).
    Исправлено: `overflow-x: hidden` перенесён **только на `<html>`**,
    `<body>` больше не имеет `overflow` вообще. Если в будущем опять
    понадобится `overflow` на `<body>` — держите в уме эту особенность,
    иначе тихо сломаете любой `position: sticky` на странице.
  - Все размеры (шрифт, отступы, высота разделителей, `gap`) — fluid через
    `clamp()` между эталонными значениями на **350px и 1908px** (макеты
    заказчика), за пределами диапазона — зажаты на граничном значении.
    `letter-spacing` задан в `em` — он и так масштабируется вместе с
    `font-size`, отдельный `clamp` для него не нужен (кроме жанров, где
    эталонные значения 0.2em/0.24em отличаются не только из-за
    font-size — там `clamp` всё же есть).
  - Жирность строки жанров — `font-weight: 400` (было `500`, заказчик
    попросил сделать чуть тоньше).
- **Шрифт:** Montserrat, добавлено начертание **600** (Semi-Bold) в
  Google Fonts ссылку — используется в `.hero__tagline`. У сайта теперь
  подключены 300/400/500/600.


## Плеер треков

- Файлы: разметка/стили — в `index.html` (секция `.tracks`, стили в блоке
  `/* ===== Tracks player ===== */`), логика — отдельно в `assets/js/player.js`.
  mp3-файлы — в `assets/audio/track-1.mp3` … `track-6.mp3`.
- **Расположение на странице:** между hero и блоком тарифов — по просьбе
  заказчика.
- **Фото справа (только на ПК):** на ширине ≥768px список треков идёт слева,
  справа — фото-панель `.tracks-photo` (`assets/img/tracks-photo.jpg`, фон
  через `background-image`, как у карточек тарифов). На мобильных
  (`@media max-width:767px`) эта панель `display:none` — и, что важно,
  современные браузеры при `display:none` вообще не загружают её
  `background-image`, так что на телефоне это не тратит трафик, только
  список треков на всю ширину. Оба столбца — `flex: 1 1 50%` с общим
  `gap: 40px` внутри центрированного `.tracks-inner`, высота фото-панели
  подстраивается под список через `align-items: stretch` — отступы
  остаются симметричными при любой длине текста. Фото обрезано по
  `background-position: 35% center`, чтобы в кадре всегда был виден сам
  диджей (на исходном фото он смещён в левую часть кадра, справа — пустой
  чёрный фон).
- **Как это работает:** один общий `<audio>` на всю страницу (не по одному
  на трек) — переключение между треками просто меняет `audio.src`. Клик по
  кнопке строки — play/pause; клик по другому треку останавливает текущий и
  запускает выбранный. Когда трек доигрывает до конца — автоматически
  включается следующий по списку; **после последнего трека плеер
  останавливается** (плейлист не зацикливается — если нужно зациклить,
  поправить `ended`-обработчик в `player.js`, одна строчка).
- **Разметка треков — статичная**, в самом `index.html` (как карточки
  галереи), а не генерируется из JS-массива: название трека — в
  `.track-title`, путь к файлу — в `data-src` на `<li class="track">`.
  Так название видно прямо в HTML (проще редактировать и не теряется для
  SEO) и переставить/добавить/убрать трек — это просто
  переставить/добавить/убрать один `<li>` блок, `player.js` сам подхватит
  любое количество строк.
- **Доступность:** кнопки — `<button>`, видимый `:focus-visible`, `aria-label`
  переключается между «Play»/«Pause» и **локализуется под активный язык**
  сайта (слушает `dj:langchange`, как и галерея).
- **Прогресс и перемотка:** тонкая полоса снизу строки (`.track-seek`),
  заполняется по ходу воспроизведения (`audio.timeupdate`) — не
  таймер/длительность трека (это была бы «лишняя информация», которую
  заказчик просил не добавлять), просто лёгкий визуальный фидбэк. Полоса
  кликабельна и перетаскиваема — клик/drag задаёт позицию внутри **текущего
  активного** трека (через `pointerdown/pointermove/pointerup`, одни и те же
  обработчики работают мышью и пальцем без разделения на mouse/touch).
  Специально **без отдельных кнопок** «вперёд/назад» — по просьбе
  заказчика, перемотка через саму полосу интуитивнее. Клик по полосе ещё не
  выбранного трека просто запускает его (как клик по play), а не пытается
  угадать позицию — у него ещё не известна длительность (`preload="none"`).
  Есть и клавиатурная перемотка: `←`/`→` с фокуса на полосе активного трека
  — шаг 5 секунд. `role="slider"` + `aria-valuenow`, `aria-label`
  локализован (`track_seek`), как и всё остальное.
  `.track-seek` начинается с `left: 60px` (а не `0`) **специально** — у неё
  `position: absolute`, она растянута на всю ширину строки, и если начать от
  самого края, её нижняя часть геометрически перекрывает нижний край круглой
  кнопки play/pause (кнопка и полоса занимают одну и ту же горизонтальную
  область слева). Клик по низу кнопки в этом случае мог попадать не в саму
  кнопку, а в полосу перемотки. 60px — это примерно ширина кнопки (40px) +
  отступ (16px) + небольшой запас.
- **Отступы вокруг Mixcloud-плеера уменьшены** (ноябрь 2025, по просьбе
  заказчика — «слишком широко»): верхний паддинг `.mixcloud` на мобильных
  `20px → 10px`, верхний паддинг `.tracks` на ПК `48px → 14px` (на
  мобильных уже было `14px`, см. комментарий в CSS) — теперь зазор между
  Mixcloud-плеером и первым треком одинаковый что на ПК, что на мобильных,
  и равен обычному гэпу между строками треков, без лишнего «воздуха»
  отдельно под сам Mixcloud-блок.
- **Mixcloud и треки сайта не играют одновременно.** Mixcloud-плеер (iframe)
  управляется через официальный Mixcloud Widget API (`widgetApi.js`, подключён
  перед `player.js`, iframe имеет `id="mixcloud-frame"`). В `player.js`: запуск
  трека сайта → `mixWidget.pause()`; событие `play` у Mixcloud → пауза нашего
  `<audio>` и обновление иконок. Проверено в настоящем Chrome в обе стороны.
  Нельзя создавать второй `Mixcloud.PlayerWidget` на тот же iframe — экземпляры
  конфликтуют (так ломался мой тест).
- **Формат файлов:** заказчик прислал оригиналы в WAV (55–82 МБ каждый —
  для сайта категорически не годится, такой вес убьёт загрузку страницы).
  Все 6 сконвертированы в MP3 (libmp3lame, VBR `-q:a 2`, ~5–7,5 МБ каждый)
  — конвертация через ffmpeg, который не входит в репозиторий (это была
  разовая обработка, сами mp3 уже лежат в `assets/audio/`). Если понадобится
  добавить/переконвертировать трек — нужен ffmpeg:
  `ffmpeg -i "входной.wav" -vn -codec:a libmp3lame -q:a 2 -ar 44100 track-N.mp3`.
- **Какие треки взяты и почему именно эти:** у исходных файлов в папке с
  треками (`Треки DiJuly для сайта.xlsx`, лист «Порядок отображения

- **Описания треков заказчик уже подготовил** (на EN/RU/ES, в том же xlsx,

- Несколько полей в исходном xlsx помечены как «уточнить» (имя артиста для
  мэшапа с «Soul Brother», имя артиста «Я Волна», треклист Tech House Mix)

## Галерея-«веер» фотографий

- Файлы: разметка/стили — в `index.html` (секция `.gallery`, стили в блоке
  `/* ===== Gallery (fan) ===== */`), логика — отдельно в `assets/js/gallery.js`.
- **Расположение на странице:** сразу после плашки соцсетей (`.social-bar`)
  и перед финальным фото с лицом (`.footer`) — так просил заказчик, фото с
  лицом должно всегда идти последним на странице. Исходный кадр `footer.jpg`
  раньше был одним цельным изображением (чёрная зона с иконками сверху +
  лицо снизу); чтобы вставить галерею между этими двумя частями, кадр
  обрезан на две части: чёрная зона просто выброшена в пользу обычного
  `background:#000` у `.social-bar` (визуально неотличимо, там и так было
  практически сплошной чёрный), а нижняя часть с лицом сохранена отдельным
  файлом `assets/img/footer-face.jpg`.
- **Как это работает:** у каждой карточки есть `offset = index - текущая`.
  От `offset` считаются угол поворота (10° на шаг), сдвиг по X (дуга),
  сдвиг по Y, масштаб, прозрачность и яркость (`filter: brightness(...)`) —
  активная карточка приподнята, крупнее (`scale 1.35`), полностью непрозрачна
  и с мягкой тенью (`.fan-card.is-active { box-shadow: ... }`), остальные
  расходятся в стороны, уменьшаются (шаг `0.1`, не ниже `0.65`), темнеют и
  слегка прозрачнее («уходят назад») — чем дальше от центра, тем сильнее
  эффект. Пересчёт идёт от реальных `offsetWidth/offsetHeight` карточки,
  поэтому один и тот же код одинаково работает на всех экранах — конкретные
  размеры карточки задаются в CSS (`.fan-card { width: 190px }` на ПК,
  `130px` под `@media (max-width: 767px)`; сцена `.fan-stage` — `820×380px` /
  мобильная `420×260px`), JS только пересчитывает геометрию дуги от них.
  Переход анимируется по `transform`, `opacity`, `filter` и `box-shadow`
  (0.5–0.65s, плавный `cubic-bezier`) — переключение между фото выглядит
  мягко, а не рывком.
- **Управление:** клик/тап по любой карточке, стрелки под веером, свайп на
  тач-экранах (порог 40px), стрелки `←`/`→` на клавиатуре — но только когда
  фокус находится где-то внутри `.gallery` (кликнули по карточке/стрелке или
  протабились туда), чтобы не перехватывать стрелки на остальной странице.
  Навигация зациклена в обе стороны.
- **`prefers-reduced-motion: reduce`:** `.fan-card` получает `transition: none`
  в CSS-медиа-запросе — переключение остаётся мгновенным, без анимации.
- **Доступность:** каждая карточка — `<button>` с `aria-label="Photo N of
  total"` (локализуется под язык сайта при смене языка — слушает событие
  `dj:langchange`), у активной — `aria-current="true"`. Стрелки — тоже
  `<button>` с `data-i18n-aria` (переведены). Счётчик — `aria-live="polite"`,
  озвучивается скринридером при смене фото. Виден `:focus-visible` outline.
- **Фото:** 12 штук из папки заказчика `D:\My Docs\Для Димы\Димин сайт\
  Димин Сайт Github\Фотоальбом на сайте`, разложены по карточкам **в
  случайном порядке** — заказчик попросил расставить рандомно и обещал
  скорректировать порядок отдельно (порядок = просто порядок `<li>`/
  `<button class="fan-card">` в разметке, поменять местами — значит
  переставить блоки в `index.html`). Лежат в `assets/img/gallery/gallery-1.jpg`
  … `gallery-12.jpg`.
  - **Как добавить/заменить фото:** портретная ориентация, соотношение
    сторон ~4:5 (под `.fan-card { aspect-ratio: 4/5 }` — другое соотношение
    тоже сработает за счёт `object-fit: cover`, но обрежет кадр по центру).
    Оптимально — сжать длинную сторону примерно до 1000px, JPEG, качество
    ~80–85% (так и сделаны текущие тестовые: ~800×1000px, 30–100 КБ каждое —
    с запасом по чёткости даже для retina-экранов при реальном размере
    карточки на экране ~100–190px).
  - Чтобы добавить/убрать количество фото (не обязательно 12) — просто

## Плавное появление блоков при скролле (reveal)

- Файл: `assets/js/reveal.js` (CSS — блок `/* ===== Scroll reveal
  (выборочные блоки) ===== */` в `index.html`).
- **Выборочно, не на всех элементах** — по просьбе заказчика: класс
  `.reveal` навешан только на Mixcloud-плеер (`.mixcloud-inner`), 3 карточки
  тарифов (`.price-col`, со сдвигом по очереди — вторая и третья появляются
  с `transition-delay` 0.1s/0.2s), ряд иконок соцсетей (`.social-row`) и
  веер фото (`.fan-stage`). **Hero и список треков без анимации** — должны
  быть видны сразу при заходе на сайт, без задержки.
- **Как это работает:** `IntersectionObserver` следит за всеми `.reveal`-
  элементами; когда элемент первый раз попадает в видимую область (порог
  15% + отступ `-60px` снизу, чтобы анимация не срабатывала впритык к краю
  экрана) — ему добавляется класс `.is-visible` и наблюдение за этим
  элементом снимается (`unobserve`) — анимация играет **один раз за визит**,
  при обратном скролле вверх-вниз не повторяется.
- Без класса `.is-visible` элемент невидим и сдвинут вниз на 28px
  (`opacity:0; transform: translateY(28px)`), с классом — плавно встаёт на
  место за 0.8s.
- **Фолбэки:** если `IntersectionObserver` не поддерживается (очень старый
  браузер) — все `.reveal`-элементы сразу получают `.is-visible` в JS, без
  анимации. При `prefers-reduced-motion: reduce` — то же самое, но через
  чистый CSS (`opacity:1; transform:none; transition:none`), без обращения
  к JS-логике вообще.

## Решённые баги и уроки (чтобы не наступать повторно)

### Слоган «Dressed in Sound» вылезал за левый край имени — РЕШЕНО

**Симптом:** первая буква слогана «D» стояла заметно левее «D» в DIJULY
(на ПК ~11px), хотя CSS-боксы `.hero__name` и `.hero__tagline` совпадали
до сотых пикселя.

**Настоящая причина:** у каждой буквы шрифта есть боковые поля (side
bearing) — пустое место между краем «ячейки» буквы и началом её штриха.
Поле задаётся в долях em, поэтому **растёт вместе с размером шрифта**.
У Montserrat «D» левое поле ~0.11em: в имени (~108px на 1440) штрих
начинается на ~12px правее края бокса, а в слогане (~23px) — на ~1px.
Боксы равны, видимые буквы — нет. Прошлые попытки сравнивали боксы
(`getBoundingClientRect`) и поэтому «не видели» проблему.

**Исправление:** `align()` в `hero-tagline.js` меряет реальные края
чернил первой и последней буквы имени (позиция символа через `Range` +
`ctx.measureText().actualBoundingBoxLeft/Right` на canvas с тем же
шрифтом) и такие же края у первой/последней буквы слогана, и ставит
слогану `padding-left/right` в px, чтобы края совпали. Пересчёт — на
`resize`, после `document.fonts.ready` и `loadingdone`.

**Проверка:** скриншоты headless Chrome на 350/393/768/1024/1440/1908 и
при масштабе Windows 125%/150%, края **белых пикселей** строк найдены
скриптом (PIL) — расхождение 0–2px (антиалиасинг) на всех ширинах.

**Урок:** когда надо выровнять *видимые* буквы разного размера — сравнивать
пиксели/чернила, а не боксы элементов. `getBoundingClientRect` у текста
показывает ячейки букв, а не их штрихи.

### Иконка play/pause в плеере не переключалась на паузу — РЕШЕНО

**Симптом:** когда трек играл (звук слышен, заголовок становится жирным, обводка
кнопки белая), в кружке всё равно горел ▶ вместо ⏸.

**Настоящая причина:** у SVG-элементов в браузере **нет JS-свойства `hidden`**
(`'hidden' in SVGElement.prototype === false`; оно определено только у
`HTMLElement`). Код делал `svgElement.hidden = true/false` — это не меняло ни
атрибут, ни отображение, а просто создавало бесполезное JS-поле на объекте.
Атрибут `hidden` на pause-иконке, прописанный в разметке, оставался
навсегда, поэтому pause никогда не появлялась. Состояние при этом считалось
верно (`is-playing` ставился правильно) — сломан был только способ показать
иконку. Подтверждено замером в настоящем Chrome: после клика
`row.classList.contains('is-playing') === true`, но `getComputedStyle` у обеих
иконок не менялся.

**Исправление:** иконки переключаются чисто через CSS по классу `is-playing`
на `<li class="track">` (`.track-btn .icon-pause { display:none }`,
`.track.is-playing .icon-play { display:none }`, `.track.is-playing
.icon-pause { display:block }`). Атрибуты `hidden` у иконок из разметки и
присваивания `.hidden` из `player.js` убраны.

**Уроки:**
- Не использовать `.hidden` на SVG из JS — только классы (или
  `setAttribute/removeAttribute('hidden')`).
- Для проверки UI-логики **недостаточно имитаций DOM в Node** — они использовали
  обычные объекты, где `.hidden` «работает», и поэтому скрывали этот баг. Надёжно
  проверять в настоящем браузере: на этой машине есть Chrome, можно запускать
  без окна (`chrome.exe --headless=new --dump-dom|--screenshot ...` против
  локального `python -m http.server`) и смотреть `getComputedStyle` и
  скриншоты.
- Побочно найдено и исправлено: `<meta charset="UTF-8">` стоял после
  скриптов GTM/Метрики, т.е. дальше первых 1024 байт, где браузер ищет
  кодировку — теперь он первым в `<head>` (иначе при открытии файла без
  заголовка кодировки кириллица может превратиться в кракозябры).
- Найдено и исправлено: `.track-seek` перекрывала нижний край кнопки
  (теперь `left: 60px`), добавлена синхронизация UI прямо при `play()/pause()`
  и подстраховка по `timeupdate` — они не были причиной бага, но безвредны.

## SEO

- `<title>` — один и тот же на всех языках (`DiJuly — Dressed in Sound»`) —
  это бренд-тэглайн, его осознанно не переводим, как и видимый слоган на
  фото.
- `<meta name="description">` — подменяется JS-ом под активный язык (см.
  выше). Если меняете текст — не забудьте поправить **все три** варианта в
  `i18n.js`, иначе для ru/es останется английский дефолт.
- `<link rel="canonical" href="https://dijuly.com/">` — есть.
- **hreflang:** добавлены теги `hreflang="en|ru|es|x-default"`, но **все**
  они указывают на один и тот же единственный URL (`https://dijuly.com/`).
  Это осознанный компромисс, а не ошибка:
  - У сайта только один URL — язык переключается в браузере через
    `localStorage`/JS, отдельных адресов `/ru/`, `/es/`, `?lang=ru` и т.п.
    нет (решили не плодить страницы).
  - По документации Google, hreflang имеет полную силу только когда у
    каждого языка — свой отдельный URL с соответствующим контентом.
    Поисковик всё равно проиндексирует то, что видит при первой загрузке —
    то есть английскую версию.
  - Тег оставлен «на будущее»/как задел: он безвреден (никаких штрафов за
    него не бывает), и если когда-нибудь появятся настоящие локализованные
    URL — донастроить будет проще, чем добавлять с нуля.
  - **Если захотите сделать hreflang «по-настоящему»** — потребуется
    рендерить разные URL под языки (например `/ru/index.html`,
    `/es/index.html`, либо серверная генерация) — это уже отдельная задача
    с дублированием контента, которой сейчас осознанно избежали.
- `robots.txt` — разрешает индексацию всего сайта (`Allow: /`), указывает на
  `sitemap.xml`.
- `sitemap.xml` — одна запись на `https://dijuly.com/` (сайт одностраничный,
  других URL нет).
- **Редирект `/index.html` → `/`:** в `<head>` стоит небольшой синхронный
  скрипт сразу после `<link rel="canonical">` — если `location.pathname`
  заканчивается на `index.html`/`index.htm`, делает `location.replace()` на
  тот же путь без этого хвоста (с сохранением `?query` и `#hash`). Нужно,
  чтобы `dijuly.com/index.html` и `dijuly.com/` не считались поисковиками
  (и пользователями) двумя разными страницами одного и того же контента.
- **Яндекс.Вебмастер:** права на домен подтверждены файлом
  `yandex_98f4901d6292babf.html` в корне — не удалять, иначе подтверждение
  надо будет проходить заново.
- `alt`-тексты у фото (`hero.jpg`, `footer-face.jpg`) сейчас общие
  (`"DiJuly"`) — можно сделать более описательными, если важно под Google
  Images.
